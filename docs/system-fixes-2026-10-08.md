# RayLink 系统修复与验收

日期：2026-10-08。修复基线：`313999996202296eb40d853d8d6368717262af2d`，分支 `codex/ai-protocol-resilience`。对应问题定义见 [系统审查报告](system-review-2026-10-08.md)。

本轮实现审查报告 R01–R11 的修复，并增加 Runtime 相同配置免重启。代码、隔离回归与原生内核验收在本地完成；没有修改生产配置、重启生产服务、推送 GitHub 或发布新版本。应用版本保持 `0.2.46`，更新后的 RayLink Node 版本为 `0.9.2`，保留旧版 `0.9.0`、`0.9.1` 的心跳、维护和升级能力。

## 已完成修复

| --- | --- | --- |

## 升级兼容与限制

- Runtime 身份与注册迁移说明见 [兼容性文档](runtime-identity-and-enrollment.md)。旧邮箱身份冲突会被隔离，不能自动重建既有错误账单；远端成功任务历史已经删除时，需成功发布新配置后才能恢复对应计量授权。
- 自动注册丢响应恢复需要新 Node 的持久化私钥及控制面回执；升级前已丢失的旧注册无法自动恢复。已有已注册 Node 不重新注册。
- 权限仍保留 Support 交付用户订阅的既有能力；Auditor 只读概览不包含订阅和协议私密字段。
- 限流为单控制面进程状态；多副本部署需要共享预算。本轮没有引入分布式架构。
- 实际配置变更仍可能重启 Runtime、中断长连接；本轮减少重复发布引发的重启，没有实现所有协议的无损热更新。
- 升级前没有持久化应用证据的 Runtime，需要一次受控应用来建立证据；不能仅凭旧数据库部署记录跳过这一步。
- ACME/provider 动态管理的证书无法完整指纹时，不将其视为已验证的免重启条件；配置应用状态与证书证据分别判断，避免定期对账循环重启。混合配置仍校验所有已知手动证书/私钥文件，变化后触发一次修复应用。
- 未来部署本轮修复后，HTTPUpgrade 客户端需刷新完整订阅。正常旧用户身份保留；少数历史身份冲突需要重新获取客户端配置。
- DNS 黑洞仍有超时预算：国内两个 DNS 同时不可用的隔离场景约 5 秒。不能将代理接管域名请求当作远端 DNS 回退已成功，也不能把 HTTPS/SVCB 提示记录当作已通过 CN-IP 过滤的地址。
- 本轮没有访问真实住宅供应商或认证 AI 账户，未验收 iPhone Wi-Fi、蜂窝网络、IPv6/NAT64、24/72 小时耐久或干净主机灾难恢复，也没有宣称整个 `check:production` 门禁全部执行通过。

## 后续优化
