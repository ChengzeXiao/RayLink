# AI API 连接稳定性修复验收

用户反馈 OpenAI、ChatGPT、Claude 访问不稳定，进一步说明是 API 偶尔重新连接。本次基线为 v0.2.36 后文档提交 `27d8389`。修复确认的配置缺陷，并通过真实内核、实际订阅和 VPS-A 验证；没有真实模型流式调用证据时，不宣称已经复现或消除全部 API 重连。

1. ChatGPT 和 Claude 的 API、OAuth 刷新、资源、WebSocket 依赖使用同一 AI 路由及 DNS。自有域名使用后缀，第三方共享服务使用精确域名，保留自定义规则优先级。sing-box、Mihomo、Egern 导出及路由诊断保持一致。以官方网络要求为依据，原生内核验证实际 DNS 和出口，而非只检查配置文本。
2. Mihomo 精确域名 DNS 规则必须被内核实际识别；验证内置依赖、用户自定义规则及相邻域名不误匹配。
3. AI 稳定出口默认必须实际进入 TCP 自动故障回退组，不能被共享 provider 的首个具体节点抢占。正常延迟波动不切换，故障仍切换到可用 TCP 候选。已有 SSE 不因后台健康探测或其他节点恢复而中断。Clash fallback 在首选恢复后可让新连接回切；需固定跨请求出口时使用独立 AI 手选。兼容传统 Mihomo 导出与共享测速导出，不清空客户端的全部缓存。
4. 验证连续 SSE、超过 60 秒的空闲后继续传输、节点故障与恢复。模拟测试与公网匿名 API 传输测试单独记录。401、Cloudflare 验证、地区限制、429 和传输错误须区分；通用健康检查通过不表示模型 API 业务可用。用户 API 密钥不读取、不输出，也不因体检触发收费调用。
5. 发布和部署保留用户、订阅凭据、月度用量、历史账单、证书及计量 Runtime。更新完整订阅并重新连接后配置才在客户端生效；旧手选“RayLink 智能”的客户端需要切回“AI 稳定出口”或固定节点。Mac / Wi-Fi 验证不代替手机移动网络验收。

测试入口沿用本项目既有公开订阅生成、路由诊断及原生代理连接边界。禁止用增大请求超时或关闭 TLS 验证掩盖断线。
