# AI 出口固定与分层诊断

本次实现不依赖第二台 VPS 的优化；审查基准为 `c896b509f7326f56dfa210bc471e9b86d3f46505`。

## 行为

- 管理员在智能路由中选择自动 AI 出口或按稳定 Host ID 固定出口。固定后 AI 自动组及手选组仅包含该 Host 的已授权、可导出协议；普通流量不受影响。所有协议仍可使用。
- 固定 Host 无可用授权协议时 AI 失败关闭，不能悄悄转为其他 Host 或 DIRECT；普通订阅仍可生成。完整 sing-box、Mihomo（两种）、Egern 配置一致。仅节点订阅不能承载路由策略，界面明确要求刷新完整订阅。
- 旧策略默认自动。旧客户端未传 aiExit 的保存不能意外解除已固定出口。主机名称变化不改变绑定；不修改用户额度、凭据或 Runtime 入站配置。
- 新增按需、固定目标、匿名的 AI 站点检测。仅测主控服务器出站，显示 DNS / TLS / HTTP 阶段与超时、网络失败、验证页、认证、权限、限流、上游失败等状态。HTTP 响应不等同真实登录或模型生成成功。
- 检测无需 API key、不发模型请求、不保存响应正文或 Cookie、不自动跳转、不接受任意 URL；严格 TLS、公网地址限制、并发与时间/响应大小限制、合并重复请求及短缓存。
- REST、MCP、管理 UI 均可读取最近结果；主动检测需 runtime.manage 权限。检测不参与自动切换，不会把 401/403/429 当作节点离线。

## 验证边界

沿用已授权的公共验证边界：策略保存 REST/MCP、用户完整订阅与真实核心加载、管理界面操作、匿名 HTTP 探针。用回归验证固定主机、缺失授权、所有固定协议故障、TLS/超时/状态分类、访问控制、重入限制及既有分流。

## 不在本次实现

双入口中转需要新增独立 Host；跨客户端严格连续失败计数/恢复冷却需要另行设计，现有 fallback / URLTest 语义保持。固定 Host 不保证其外部 NAT 出口地址永不变化。服务器探针不代表手机蜂窝网络，也不证明账户可用或不被封禁。
