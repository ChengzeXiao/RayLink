# AI 网站全协议恢复与连接稳定性

用户要求 Claude.ai、OpenAI/ChatGPT 及其他 AI 网站可通过当前节点的各协议访问，页面、验证和流式连接都需要检查。

## 可验收行为

- AI 自动策略保留所有可导出的公网协议，TCP 全部故障时能使用仍健康的 TUIC/Hysteria/Hysteria2 等候选。Mihomo/Egern 采用 TCP 在前的有序 fallback；sing-box 使用高容差 URLTest 保留健康的当前出口，不宣称提供其不支持的严格有序 fallback。
- 每个可用协议仍能独立手选，普通网站选择不覆盖 AI 手选。客户端本地健康检测决定故障恢复，不依据服务器侧 UDP 测试永久排除某协议。
- 健康候选延迟变化不强行关闭已有 SSE/WebSocket；故障切换只恢复后续连接，已经中断的应用请求仍由客户端重连。
- 已核实的 AI 专用入口、API、登录与资源域名在 DNS、路由诊断和完整订阅中保持一致；共享平台按精确域名匹配。自定义规则和内网优先级保留。
- 真实核心故障回放验证 TCP 失效而 UDP 存活的路径。独立真实加密协议测试验证 WebSocket Upgrade、双向传输、大帧、长空闲恢复和正常关闭；受控断流负例必须失败。

## 证据边界

公网矩阵分别记录 TLS/代理传输、HTTP 状态、重定向、人机验证、认证和地区错误。匿名 API 401、Cloudflare 403 均不等同于已登录网站或模型回答成功。当前单 VPS 上的多种协议共享一个公网出口；协议切换无法改变出口 IP 的站点信誉或地区限制。新增域名覆盖也不能被称为已经证明的 Claude 主站故障根因。

当前公网启用 7 个协议；其他支持但未启用的协议以本地互通测试验证，不自动新增监听端口或改动用户协议配置。手机移动网络、真实账户与付费模型请求必须单独验收。
