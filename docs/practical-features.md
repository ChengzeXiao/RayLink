# 实用功能设计与交付顺序

更新：2026-10-01。基于 RayLink 当前 Node.js + SQLite 控制面、sing-box 1.14.2、多 Host 拉取式发布与统一订阅架构。本文的后三项是设计，不代表已实现。

## 1. 运行体检与诊断报告（本轮已实现）

**解决的问题**：节点进程在线不等于代理可用；发布完成、协议检测、用户计量和备份状态分散，管理员很难判断接下来处理哪里。

入口：系统 → 运行体检。首次进入、手动刷新或导出时调用 `GET /api/operations/readiness`。沿用管理员 `read` 权限；匿名访问拒绝。多个并发请求共用一次检查，避免重复扫描备份。

检查内容：最新发布与全部目标回执、公开客户端入口、Runtime 与近期心跳、关键权益撤销、用户计量、15 分钟内的完整握手及外部访问、智能分流模式、规则库、最新备份现场 SHA-256/SQLite 校验、运行告警。

结果分别标记“通过 / 异常 / 警告 / 待确认”，显示证据时间和处理入口。缺失、过期、时钟异常、仅 TCP 端口成功、模拟运行、配置未应用均不能作为完整协议健康证明。报告是生成时刻的快照；常规页面刷新不会偷偷重测或重启服务。

报告导出字段采用白名单：固定检查编号、状态、建议与时间。主机以序号标识；不导出地址、主机名称、用户资料、订阅地址、凭据、原始配置、错误堆栈或磁盘路径。页面可以用当前列表名称辅助定位，导出不会携带这些名称。

**验收**：匿名 401；审计员可只读；删除真实备份文件后检查失败；最新发布失败覆盖旧 active 状态；没有公开入口时不得全绿；配置变动失效旧探测；页面建议跳转与下载可用。体检不会证明手机真实网络质量或备份恢复演练已通过。

## 2. 用户流量对账（下一优先级）

**解决的问题**：用户质疑“为何扣了这些流量”时，目前总额不足以解释重启、延迟上报、跨节点用量与异常采样。

在用户详情新增“流量明细”：按日期、Host 展示上行、下行、计入额度、最后采样时间；可展开 Runtime 实例切换、拒绝样本、历史样本只建基线等原因。总额来自账本与 `daily_user_usage`，禁止用主机网卡流量代替用户计费。

新增只读聚合接口 `GET /api/users/:id/usage?from=&to=&hostId=`，查询范围最多 90 天、分页且服务端验证日期；服务人员只能看到其角色已允许管理的用户范围，审计导出记审计事件。旧数据不足显示“无法核实”，不得捏造起止计数。

任何人工调账都独立记录原因、操作者、正负额度及关联事件，采用幂等请求编号，不直接覆写历史账本。普通诊断不自动退费或追加扣款。

**验收**：A100 → B20 → 延迟 A120 → B30 总计 150；重复样本、乱序样本、跨 Host 同样本编号不重复收费；旧库升级可解释保留账本与无法恢复的历史差异；筛选合计与账本一致；导出不含协议凭据。

## 3. 灰度发布与可靠恢复（稳定性优先）

**解决的问题**：现在能生成不可变快照并回滚，但一次错误配置仍可能影响多个节点；进程在本机应用与远端意图落盘之间退出，也不能靠内存锁完整恢复。

先补可靠发布基础：在同一数据库事务保存 Deployment、Target 与待执行意图，后台领取执行，使用每 Host 单调递增配置代数和持久租约。Node 记录已应用的代数、配置哈希与回执；旧代数不可覆盖新代数。启动时核对实际配置哈希与未完成意图，显示“待对账”，避免盲目重复重启。

普通配置选择一台低风险 Host 做金丝雀：保存原快照 → 内核校验 → 应用 → 运行状态与完整握手验证 → 两个独立观测窗口后逐批扩展。窗口长度、探测目标和成功门槛需在目标环境标定，初始可用 5 分钟窗口。失败暂停后续批次，原子恢复已受影响目标并确认服务与协议实际恢复；恢复失败升级为严重告警。

**关键例外**：禁用用户、配额耗尽和凭据撤销不能等待普通灰度窗口，走优先撤销队列，覆盖较旧待执行任务；离线节点持续显示未确认，不声称即时撤销。

**验收**：在生成后、应用后、回执前、回执成功后分别强制退出再启动；最终意图、真实配置和目标状态一致。单节点验证失败不扩散；新旧任务乱序、租约到期、重复回执不能恢复旧权限；首次发布失败必须停止候选，停止失败必须明确报告。

## 4. 客户端网络诊断与配置建议（网络质量优先）

**解决的问题**：主控到节点的成功探测无法反映手机运营商的 UDP 限制、DNS 故障、IPv6 路径及 Wi-Fi/蜂窝切换。

用户中心提供主动诊断向导，先说明流量消耗和可分享字段。第一阶段由用户选择客户端与故障现象，导出对应客户端诊断步骤及建议配置；浏览器只能报告它实际能够测量的 HTTPS/DNS 相关现象，不假装能测试任意 UDP、TUN 或 MTU。第二阶段再通过支持的客户端扩展收集经过明确同意的 DNS、TCP、UDP/QUIC、IPv4/IPv6 和切网测量。

仅允许预设的 RayLink 检测端点及受管 Host，禁止任意 URL 代理探测。限频、限定并发、限定最大字节；不记录访问历史，不默认上传完整 IP 或原始客户端配置。诊断与实际用户浏览业务隔离。

建议提供三个清晰可选档位：移动稳定（保留可用 TCP 入口）、低延迟（有近期数据支持时才推荐 QUIC）、手动固定（用户保留决定权）。建议说明证据来源与时间；缺乏足够样本时不自动切换。AI 会话优先保持出口稳定，故障才换线；任何档位均不得在代理全失败时擅自直连受保护流量。

**验收**：在真实手机上分别测试 4G/5G、Wi-Fi、UDP 丢弃、DNS 失败、IPv6-only/NAT64、前后台及切网；记录成功率、中位/P95 首连接、恢复耗时、出口是否变化及耗电/探测流量。模拟测试先覆盖策略边界，真实网络结果决定是否默认启用，不用本地压测数字替代手机体验。

## 范围与发布门槛

先交付只读体检，再做对账；可靠发布与客户端诊断可分别推进。后三项涉及数据模型、状态恢复或客户端能力，不塞入本轮补丁，以独立验收闭环交付。所有上线均需先完成目标 Linux/systemd 环境验收、备份恢复演练及真实移动网络验证。
