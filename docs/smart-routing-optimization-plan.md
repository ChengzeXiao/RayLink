# RayLink 智能分流优化建议

日期：2026-10-01。代码基线：`ec468a4`。本次为分析与设计建议，未修改运行配置，也未进行线上或手机测试。

后续实现与实际验收见 [智能分流修复与模拟验收](smart-routing-implementation.md)；本文保留实施前的问题与完整目标，不能把下列计划当作全部已验收能力。

## 结论

现有实现已有国内直连、AI 分组、默认代理与节点回退基础。优先补齐“目的地判定、DNS、出口选择”的一致性，再引入按网络环境调整的节点选择。不要用一次 HTTP 延迟探测替代分流正确性或业务可用性判断。

默认产品行为建议为：国内常用服务直连，已知境外服务走代理，AI 使用稳定出口，未知目标按最终解析 IP 补充判断；无法可靠分类时默认代理，不因代理故障自动改为直连。

## 目标规则顺序

1. 基础通信：DNS 接管、本机与明确的局域网访问保持可用；实际 IP 的本地绕行避免不必要解析。
2. 用户显式规则：直连、代理、AI、拦截；保持明确优先级。需要解析才能匹配的 IP 规则按其优先级处理，不能为减少 DNS 查询而静默重排。
3. AI 服务域名：主站、登录、API、静态资源与上传域名使用同一 AI 出口策略。
4. 明确境外服务：使用可维护的代理域名集合，避免仅因某次 DNS 得到中国 IP 就覆盖明确代理意图。
5. 明确国内服务：使用完整国内域名集合直连；`.cn` 只是一项分类依据，应允许例外覆盖。
6. 未知目标：域名先获得可用于路由的解析结果，再判断私有/中国 IP；其余走默认代理。解析失败按内核实际错误/重试能力处理，不宣称一条默认代理规则能自动挽救全部 DNS 失败。

广告、追踪拦截建议保持可选，单独启用并支持例外，避免默认干扰登录、支付、验证码。

## DNS 应与目的地策略绑定

- 局域网、企业 split-DNS：系统或企业 DNS，保留私有域名解析；对网络切换后的本地域名限制过期缓存。
- 明确国内目标：可信国内加密 DNS，经直连出口。
- 明确代理目标：境外加密 DNS，经代理出口；AI 目标跟随 AI 出口，减少解析位置与访问出口不一致。
- 节点域名：独立 bootstrap/Host 映射，避免“先连代理才能解析代理地址”的依赖环。
- 未知域名：建议默认先经稳定代理使用境外加密 DNS，再按响应分类；中国目标可用国内 DNS 优化 CDN。代价是未知国内域名首次分类仍依赖代理，因此完整国内域名基线很重要。1.14.2 可用 `evaluate` / `match_response` / `respond` 做 DNS 响应判定；必须验证超时、混合 A/AAAA、CNAME、NXDOMAIN 与路由最终出口的一致性。GeoIP 的“任一地址命中”不能证明整个响应都属于国内，`respond` 也不会自动过滤其余地址；混合响应应保守走代理或进入专门处理流程。不要并发查询所有 DNS 后无条件接受最快回答。
- 当前 5s 超时、4096 缓存、30s 过期宽限保留为初始实验值；实际体验还取决于应用重试、传输与系统 DNS，不能承诺所有 UDP DNS 在 5s 内返回错误。

## 节点选择：稳定性与速度分开

基础版采用客户端已有能力：Mihomo/Egern 可用顺序回退；sing-box 1.14.2 原生 URLTest 只有单 URL 与延迟容差，不能生成不存在的 fallback 或多目标权重字段。

- 移动网络默认使用至少两个可达 TCP 入口作为稳定候选；UDP 路径经当前客户端网络验证后再参与自动选择。服务端健康只用于过滤明显坏节点。
- Wi-Fi 可使用稳定候选测速；需要允许用户固定出口。
- AI 优先会话连续性，主出口正常时不因几十毫秒差异切换；故障才切备用，新连接走新出口。既有 TCP 连接不能凭规则无损迁移到另一个公网 IP。
- 区分“代理连接采用 UDP/QUIC”与“代理能转发用户 UDP”。当前 TCP-only Shadowsocks 不能承担 UDP 应用；UDP 游戏/通话应按实际 relay 能力选择，不能把所有 UDP 都拦截。
- Wi-Fi/蜂窝切换后重测当前路径；sing-box 自身已有默认接口变化触发 URLTest 的机制，应利用并验收，避免重复实现或误称当前完全没有重测。

高级自适应需要客户端侧观测/控制，当前控制面生成订阅无法独立实现全套体验评分。建议试验参数为：活跃网络探测 30–60s、连续失败 2 次触发切换、恢复成功 3 次后重入、约 2 分钟防抖；这是目标参数，需按内核可表达能力与手机耗电验证，不是现有配置承诺。多目标成功率、DNS/握手/首包与抖动作为后续观测指标，单目标 204 仍只是有限健康信号。

## 实施顺序

**第一批：分流正确性。** 修正 sing-box 域名到 IP 的匹配流程、Egern 顶层策略绕行、自定义 DNS 映射；统一诊断语义；同一组行为样例验证三端。

**第二批：规则维护与降级。** 用同一逻辑源构建各端格式，清单包含版本、时间、来源、摘要、统计；候选规则先编译并执行行为样例，再发布。无更新保留旧版；首次启动有完整随包基线；UI 显示正在使用的版本和降级状态。

**第三批：移动网络与 AI。** 独立 AI 出口策略；按客户端能力选择故障回退/稳定测速；补网络切换、UDP 阻断和 IPv6 测试。Loon 先明确节点订阅边界，再单独决定是否实现完整配置。

## 验收样例

| 场景 | 验收结果 |
| --- | --- |
| 国内常见站点、CDN、未在域名表内但实际中国 IP 的域名 | 在 SOCKS 域名模式和 TUN IP 模式都命中预期国内策略 |
| AI 主站/登录/API/流式请求 | 出口策略一致，正常测速不主动切断会话 |
| 境外明确代理域名解析出中国 IP | 仍遵从显式代理规则 |
| exact/suffix/IP 规则重叠、自定义 DNS 与默认分类冲突 | 优先级与诊断一致；客户端无法表达时拒绝或明确报告能力限制 |
| 本地域名、私有地址、系统 DNS、IPv6/NAT64 | 保留内网访问，且不依赖不可达的地址族 |
| 冷启动离线、损坏规则集、DNS 超时、单节点失败、UDP 全部阻断 | 有明确降级和可用备用路径；原定代理流量不自动直连 |
| Wi-Fi ↔ 蜂窝各 10 次切换，持续流式与视频 30 分钟 | 记录真实新请求恢复时间、失败率、切换次数与耗电变化 |
