# 月度流量额度

用户的流量额度按北京时间的自然月计算。`quotaGb` 表示每月额度，`usedGb` 表示本月已用；每月 **1 日 00:00，Asia/Shanghai（UTC+08:00）** 开始新的周期。额度不随重置改变，未使用的余额不结转到下个月。界面沿用 GB 单位，计量换算为 1 GB = 1024³ 字节。

## 首次启用与月初重置

首次启用月度计量时，系统立即将现有用户的旧累计用量归档，并将本月已用清零。旧累计属于启用前的历史记录，不会被冒充为某个完整自然月的用量。此初始化只执行一次，之后重启主控不会重复清零。

每次跨过月界，上一周期用量归档，当前周期从零开始。主控在月初停机时，恢复后补执行周期转换；无需管理员手动清零。重置不改变用户每月额度、到期时间、节点范围、账号密码或订阅地址，也不会解除管理员设置的停用状态，或让已到期用户重新获得服务。

Runtime 仍按实例上报累计计数。月度重置保留计量 checkpoint，不通过清空 Runtime 计数来重置额度，因此不会在下一次上报时把旧累计重新扣入新月份。

## 月界计量边界

累计计数只能说明两次采样之间一共传输了多少字节，无法精确还原这些字节发生在午夜前还是午夜后。对于跨越月界、无法准确归属的累计样本，系统先建立新周期基线，之后只累计新增字节。这个策略可能少计边界附近的一小段流量，但不会将无法区分的旧月用量扣到新月。

停机期间跨月、延迟上报及 Runtime 实例变化也遵循相同的保守原则。月度额度是计费和使用上限，不意味着服务器网卡流量统计也按相同口径清零。

## 管理界面与用户中心

用户列表和编辑表单显示“本月已用 / 每月额度”，并给出“下次重置（北京时间）”。用户中心同时显示本月已用、每月额度、本月剩余和节点范围。重置日期显式使用 `Asia/Shanghai` 格式化，不受浏览器、电脑或手机所在时区影响。

界面依据服务端的 `usagePeriod` 确认月度计量状态。旧接口没有该字段，或周期信息不完整时，界面保留“已用流量 / 流量额度”，显示“自动重置状态待确认”，不会根据本地日期自行假定服务端已经启用月度重置。

周期元数据示例：

```json
{
  "key": "2026-10",
  "timeZone": "Asia/Shanghai",
  "startsAt": "2026-09-30T16:00:00.000Z",
  "resetsAt": "2026-10-31T16:00:00.000Z",
  "lastResetAt": null
}
```

`resetsAt` 在界面中显示为 **2026/11/01 00:00（北京时间）**。用户记录携带自己的周期信息，管理员 bootstrap 还提供全局当前周期；用户中心使用 `profile.user.usagePeriod`。

## 管理员校正用量

普通修改用户名称、额度或节点范围时，界面不提交未改动的 `usedGb`，避免把旧表单里的用量覆盖到已经重置的新月份。管理员明确修改已用流量时，界面同时发送原表单的 `usagePeriodKey`。若保存时月份已经变化，服务端返回 `409 USAGE_PERIOD_CHANGED`；应重新打开该用户，读取新周期后再决定是否校正。

用量校正不会重新生成协议凭据或订阅地址。月度用量归档由服务端保存，可通过管理员 API `GET /api/users/:id/usage-history`、本人门户 API `GET /api/portal/usage-history` 或 MCP `users_usage_history` 查询；返回历史用量、当期额度及人工调整记录，不返回凭据。管理界面暂未新增历史记录页。
