- 9/9 严格 TLS + 101 Upgrade + 双向文本/256 KiB 二进制 + ping/pong + 70 秒无应用心跳后继续传输 + normal close。主动断流负例正确失败。
- 新回归已接入 `check:ai`，由 `check:production` 和正式发布门禁运行。进程与 controller 操作有明确超时、loopback 绑定和退出清理。

## 生产基线（升级前，2026-10-04）

使用当前完整现代 Mihomo 订阅、内部探测凭据和独立客户端；显式绑定 Mac `en0`，不借用系统 TUN 作为证明。

- 默认 AI 策略及 7 个启用协议逐一访问 10 个网站/API，共 80 次 HTTPS 请求均有响应，无代理、TLS 或传输超时。
- Claude.ai、ChatGPT、Perplexity 各组均返回 Cloudflare challenge；OpenAI/Anthropic API 返回匿名认证 401；Gemini/Grok/Copilot 返回 200；AI Studio/Poe 返回重定向。**80 次传输响应不是 80 次网站业务成功。**

## 未发布候选 v0.2.38 的门禁修正

正式发布复验 [37185853242](https://github.com/ChengzeXiao/RayLink/actions/runs/37185853242) 检出了旧 `route-failover-check.mjs` 的过期断言：TCP 全故障而 UDP 仍健康时，测试仍要求 AI 请求失败。固定等待 1500ms 使这一断言依赖探测时序，PR CI 因而未稳定检出。

修正后显式等待 AI 经 UDP 恢复，再停止 UDP，验证所有候选失败时 AI 与普通流量均禁止泄漏到 DIRECT。普通 TCP 默认仍保持自己的候选池边界；sing-box 不再被测试强制要求故障后只能选 TCP。原候选没有生成公开 Release 或部署；保留其 Git 标签，正式版本顺延 v0.2.39。
