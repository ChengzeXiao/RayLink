# v0.2.34 发布审查与 QA

基线：v0.2.33 / b602faab36ff81a000ad55cc93d467ce650bf285。需求：[自然月流量额度规范](../monthly-usage-spec.md)。首次升级立即归档并清零由用户明确确认；月界采用 Asia/Shanghai。

## 验证范围

- Store 公共接口：首次旧库迁移、重复打开、跨月/跨年/闰月、停机恢复、时间回退、凭据及禁用/到期状态保留、人工调整历史。
- 计量：重复/乱序、同月升级基线、跨月旧样本补历史、未知 Runtime 实例、未来月份样本拒绝；不通过清除 Runtime 计数器实现重置。
- HTTP：真实月界自动协调有效用户配置；无请求的月界定时器；旧周期调整 409；历史参数限制。
- 门户与 MCP：本人历史隔离，匿名拒绝，read Token 历史查询和凭据排除，禁止只读 Token 修改用量。
- 远端配置：重试超过 5 次、pending/claimed 任务被替换后继承持续重试、配置快照当前但实际节点尚未应用时保持待同步。
- 界面：本月用量及北京时间日期，缺少周期元数据时不假定已启用；普通编辑不回写旧用量。

## 审查

Standards 与 Spec 两轴审查均以以上固定基线和规范进行。发现并关闭的核心问题：远端恢复配置不能只凭发布快照认定应用成功；持续重试属性需要跨任务替换保留；节点心跳与回执不能等待配置发布。普通用户编辑和显式调账分别处理，避免旧表单覆盖新周期用量。

最终两轴均无剩余阻断发现。2026-10-02 本地 `npm run check`：555 通过、0 失败、1 跳过；跳过项要求真实 1.14.2 Runtime，发布流水线显式提供该构建执行。本地未将系统安装的 1.13.14 当作 1.14.2 验收。

生产数据库的独立副本迁移通过：7 名用户、3 名管理员的身份、凭据和权限数据保持一致；旧累计逐用户精确归档，首次当月用量清零，检查点和账本保留，完整性/外键检查通过；写入新用量后重新打开副本，验证不会再次重置。此结果是副本迁移验证，实际上线状态另行验证。

## 发布门槛

`npm run check:production` 包含语法及完整测试、9 协议实际传输/计量/撤销、DNS 故障与恢复、智能路由/回退及内存 soak。CI 使用批准的真实 sing-box 1.14.2 计量构建；AMD64、ARM64 原生安装、HTTPS、MCP、BBR、更新及回滚通过后才生成 Release。

最终测试数与每个架构结果以该 tag 的 GitHub Actions 日志为准。生产部署另在数据库副本上比较用户和管理员凭据、归档用量、首次清零与再次打开的幂等性，再执行带备份升级和线上状态/订阅/协议验证。

## 边界

不声称采样间隔内的流量能精确分配到月界两侧；采用保守首样本基线，详见月度计量说明。此版本不改变云安全组或网络运营商条件，也不证明公网移动网络性能提升。
