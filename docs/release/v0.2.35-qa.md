# v0.2.35 发布审查与 QA

基线：v0.2.34 / 5cff12ace1cf1ce93f730a2413c976fcc2eaa731。需求：[TUIC 兼容与自动配置规范](../tuic-compatibility-spec.md)。

## 故障定位

生产节点的证书有效、DNS 指向正确、公网 UDP 8447 放行、用户订阅凭据与运行配置一致。相同目标上 sing-box TUIC 可以访问公网，Mihomo 1.19.25 使用 RayLink 导出代理稳定失败，错误为 `tls: server did not select an ALPN protocol`。客户端单独添加 h3 仍失败。

本地隔离测试仅为服务端和客户端加入 h3 即恢复完整传输；去掉服务端 ALPN 后重现失败。测试使用独立随机凭据、自签证书与回环地址，证书跳过验证仅用于该隔离夹具；生产导出与上线公网验证保留证书验证。

## 验证范围

- 公共配置生成接口覆盖 certificate、ACME 的服务端、订阅与协议探测；Mihomo/Egern/Egern Profile 均输出 h3。
- 真正启动 Mihomo 与 sing-box，分别通过 TUIC 传输并比对完整 131072 字节内容。
- 同一夹具移除服务端 ALPN 后必须发生 ALPN 握手错误，不能以本机直接连接伪造成功。
- 外部导入配置不设置 ALPN 时，格式转换器继续保持其配置意图。
- 远端 Node 与主控探针配置一致；Node 0.9.1 修复远程 ALPN，0.9.0 仍可心跳、维护及滚动升级。
- 自动安装检查已启用入口协议的 TCP/UDP 防火墙和监听状态，保留已有端口、凭据与专门配置。
- 升级保留用户、管理员、协议凭据和自然月数据，运行配置发布后再次验证真实公网 TUIC、其他启用协议、订阅与 MCP。

## 发布门槛与边界

`npm run check:production` 增加 `check:tuic`，并保留完整测试、9 协议实际传输/计量/撤销、DNS 故障恢复、智能路由回退和内存 soak。CI 提供 sing-box 1.14.2 计量构建及按官方 SHA-256 校验的 Mihomo 1.19.25；缺少二进制的跨客户端测试直接失败。

本机快速验证使用 sing-box 1.13.14 / Mihomo 1.19.25，不能替代 CI 的 1.14.2 验收。最终测试数与 AMD64、ARM64 原生安装、HTTPS、MCP、BBR、更新回滚结果以 tag 对应 Actions 日志为准。

用户未确认具体手机客户端版本。公网测试机的传输结果不等同于用户 Wi-Fi / 移动网络最终体验；升级后需更新 TUIC 订阅并在手机重试。

## 两轴审查

Standards 审查未发现硬性规范违反或需要处理的维护性问题。Spec 审查发现并修复两处：README 必须区分首次自然月迁移与本次升级；仅本机 IPv6 地址的展开、映射写法不能新增公网防火墙规则。后者使用标准网络地址匹配并覆盖五种回环表示，修前错误用例失败、修后通过。

针对性配置、协议继承及回滚测试通过；真实跨客户端两项传输与 ALPN 负向控制通过。本地完整测试发现 CI 命令换行导致旧文本断言失效，已支持 shell 续行并纳入 Mihomo 与 `check:tuic` 发布门槛，定向复跑通过。最终整体验收由本次发布的 CI 全量重跑确认。

首轮 Linux 候选验收的 566 项测试全部通过，后续协议测试阻断了发布：远程 Node 内置探针尚未同步 ALPN。补齐远端实现并提升 Node 至 0.9.1 后重新执行整套流水线；失败候选未发布 Release、未部署服务器。
