# v0.2.33 发布审查与 QA

基线：v0.2.32；范围：用户、权限、MCP、SSH 接入、安装/更新/回滚、Runtime、分流/DNS、订阅、UI 状态和发布产物。最终结果以该版本 GitHub Actions 原始日志为准；Release 依赖全部发布门槛成功，源码提交本身不代表线上 VPS 已部署。

## Standards 审查

审查项目约定、权限边界、持久化、并发重试和域名一致性。发现并关闭 P2：已绑定域名的 Host 修改 IP 后会保留旧绑定，导致 DNS 与订阅不一致。现在修改前返回 `HOST_DOMAIN_MIGRATION_REQUIRED`，不改变已有数据；无域名绑定的地址修改及名称修改继续可用。新增真实 Store/域名服务/客户端配置回归。

## Spec 审查

对照自动完成安装、协议/订阅、BBR 状态和系统更新需求，发现并关闭：

- P1：主控 Runtime 的只读 systemd 沙箱阻止 ACME 持久化。增加独立可写 state 目录，更新器备份/恢复 unit，不中断运行中的 Runtime。
- P2：首次安装中断留下 Caddy 或应用目录后无法续接。增加私有安装标记及数据库状态检查，保留证书、凭据和加密密钥，仅恢复自身未完成安装，拒绝覆盖外部 Caddy。

安装状态、安装脚本和升级回滚定向回归先复现故障，再验证修复。

## 完整客户端与网络审查

发现并关闭两项 P1，原有仅检查片段的配置测试未能覆盖：

- sing-box 1.14.2 拒绝国内 DNS 的空 direct detour。修复后启动完整生成配置，保留原始 DNS、规则和 outbounds，仅用 loopback socks 替换 TUN 入站以隔离测试机路由。
- IP 自签名主控的远程 SRS 下载因证书链不受信而失败。改为完整 inline 规则；测试从首次初始化、创建用户、发布到各订阅 API 及真实内核冷启动，且继续验证公开可信来源保留远程规则。

真实 1.14.2 本地隔离验收：9 种协议各传输 245,760 bytes，计量有效，禁用后新连接拒绝；DNS 100% 丢包、5 秒无缓存超时与恢复刷新；普通/IP 优先路由、AI 稳定出口、TCP 回退、全故障关闭和现有流保持。macOS Naive 客户端使用官方 CGO 版本，服务端使用计量构建；Linux 发布使用带配套 Cronet 的批准构建。

## 发布门槛

1. `npm run check:production`：语法、单元/API、安装升级回滚、权限/审计/去重、协议、传输、DNS、路由、内存 soak。
2. PR 在 Node.js 22/24 运行上述门槛，并增加 AMD64 真实安装验收。
3. 发布在 Ubuntu 24.04 AMD64、ARM64 原生 runner 构建、校验 Runtime，打包后运行 `tests/linux-install-smoke.sh`。
4. 真实安装验收核对 Caddy、主控、sing-box systemd 服务；使用指定 CA 的 HTTPS；创建用户并验证完整订阅启动、代理传输/计量/撤销；MCP 初始化、scope 与 Token 撤销；BBR API 与 sysctl 一致；进入实际 Runtime mount namespace 验证 ACME 可写、配置只读。
5. 对实际安装执行应用更新并检查 Runtime PID、账号与用户保留；注入启动失败，验证应用/数据回滚和原 Runtime 连续运行。
6. 两架构全部成功后上传 tar.gz、SHA-256、manifest、SPDX 和安装器，生成构建来源证明，使用本版本策划的 Release Note 发布。

`tests/linux-install-smoke.sh` 仅允许 root 在显式设置 `RAYLINK_DISPOSABLE_SYSTEM=1` 的全新 Linux VM 运行，拒绝覆盖已有安装。

## 未声称的结果

测试未替用户部署任何真实 VPS，未修改目标云安全组，未证明公网 CA 颁发/续期或手机蜂窝网络吞吐提升。Linux 内核不支持 BBR 时允许其余功能继续，状态必须明确；本地 macOS dry-run 不表示远程节点已经运行。绑定域名的 Host 地址迁移需独立 DNS 迁移流程，当前会明确拒绝直接改 IP。
