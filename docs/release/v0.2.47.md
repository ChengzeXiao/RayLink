# RayLink v0.2.47

系统审查 R01–R11 的稳定性、安全、注册及计量修复，新增经过实际应用证据确认的相同配置免重启。控制面版本 `0.2.47`，RayLink Node `0.9.2`；审批 sing-box Runtime 仍为 `1.14.2`，本次应用升级不替换 Runtime/Cronet 二进制。

## 修复内容

| 范围 | 更新后的行为 |
| --- | --- |
| R01 凭据权限 | REST/MCP 明确检查 `secrets.read`；Auditor 无法读取订阅 bearer，无 Runtime 管理权限的角色只接收脱敏 Host 协议。成功敏感读取保存脱敏审计。Support 保留既有订阅交付能力。 |
| R02 回滚授权 | 恢复历史协议与拓扑时按当前权益和当前凭据重编译，不恢复停用、到期或超额用户。当前上游损坏不阻止恢复有效历史配置；历史上游本身无法解密时仍拒绝回滚。 |
| R03 注册恢复 | Node 先持久化 X25519 密钥，控制面原子消费令牌并保存加密回执。同一密钥可在响应丢失后重试恢复，不允许不同密钥接管。 |
| R04 计量身份 | 新用户使用不可变 ID 身份；现有安装保留捕获的 Runtime 用户名。旧邮箱别名不转移归属，删除后保留隔离标记，多别名共享计量水位，冲突历史按隔离处理。 |
| R05 Host 计量授权 | 远端仅对成功应用配置中出现过的用户计量，按授权时间区间接受合法迟到样本；排队配置不授予计量权限。 |
| R06 登录竞态 | 异步校验密码后复核当前哈希、身份及状态，防止密码重置前的在途旧密码登录重新获得访问。 |
| R07 并发限流 | 密码校验前预留来源、账户及全进程预算，成功和异常路径均释放自己的额度；字段类型先验证，避免绕过账户限制。 |
| R08 操作反馈 | 发布/回滚提交成功与页面刷新失败分别提示，保留部署 ID，不因读取失败提示重复写入；各 Host 结果在部署记录核对。 |
| R09 应用证据 | 本机读回活动文件哈希，绑定 systemd InvocationID 并校验已知 TLS 资产；缺少证据或发生漂移时显示未确认并重试修复。 |
| R10 HTTPUpgrade | Mihomo 使用 `network: ws` 与 `ws-opts.v2ray-http-upgrade`，保留 path、Host 和 headers，覆盖 VMess/VLESS/Trojan。 |
| R11 普通流量 DNS | 启用住宅 AI 出口时，普通域名终止路由前执行 Runtime DNS 解析和备用回退；AI 原始域名继续交给上游，普通 Google 与浏览路径不扩大到住宅。 |

本机和远端仅在活动配置、在线实例、持久化应用证据及已知证书内容一致时跳过重启。远端仍检查防火墙和协议，ACME challenge 端口冲突提前拒绝。动态证书不能完整指纹时不满足免重启条件，但配置应用与 TLS 证据分开判断，避免每次对账循环重启；混合配置仍校验已知手动证书。实际配置或证书变化仍可能中断已有连接。

## 升级说明

- 本次增加 SQLite schema 与身份/Host 授权迁移。使用默认完整应用和数据回滚，**不能启用 `RAYLINK_PRESERVE_DATA_ON_ROLLBACK=true`**；升级器先在隔离副本检查迁移、数据库完整性和外键。
- 正常旧用户身份、凭据与本月用量保留。历史身份冲突会隔离，不能自动重建既有错误账单；远端成功任务历史已删除时需重新成功发布配置，才能恢复对应计量授权。
- 旧 Runtime 首次建立应用证据需要一次受控应用，可能短暂重连。上线后核对活动配置哈希和 `configurationIntegrity`，并观察两个以上 60 秒对账周期的实例稳定性。
- Node 0.9.0/0.9.1 保留心跳、任务与维护升级能力，可先升级控制面，再逐台更新到 0.9.2。已注册 Node 保留原身份，不重新注册；注册丢响应恢复需要新 Node 已保存的密钥，无法追回升级前已经丢失的旧注册。
- HTTPUpgrade 设备需刷新完整订阅并重新连接；少数历史身份冲突也需要重新取得客户端配置。前端资源版本同步更新，避免继续缓存旧发布提示。
