这不是全仓库安全审计。没有生产服务器访问记录、手机日志、运营商与客户端版本，不能认定已复现用户报告的蜂窝网络故障。

## 已定位并修复

| 级别 | 触发条件与影响 | 修复 |
| --- | --- | --- |
| P1 | 用户 POST 已提交，随后 bootstrap 失败；前端抛出保存失败，旧表单仍可能重复 POST，收到邮箱已存在 | 写入成功立即绑定返回的用户 ID；刷新失败单独提示，不否认保存成功；再次保存走 PATCH |
| P1 | 创建接口返回 `runtimeSync.pending`，新用户详情分支仍显示可立即使用的成功提示 | 新用户提示保留“等待应用”和发布失败原因 |
| P1 | Egern 自定义 `proxy` 规则引用不存在的 `RayLink 代理` 策略组 | 生成对应代理选择组；校验规则引用存在 |
| P1 | Shadowsocks 服务端配置 `network: tcp`，客户端却声明 UDP relay 可用 | sing-box 限定 TCP；Mihomo/Egern/Loon 导出相同能力，不再将 UDP 发给不存在的服务端监听 |
| P2 | Mihomo 同一域名多条路由按优先级首条生效，DNS 字典却被后续低优先级规则覆盖 | 重复 DNS key 使用首条；本地域名 DNS 保留最高优先级 |
| P2 | Mihomo 顶部私网 CIDR 规则可能先触发 DNS，再到达域名规则，弱网增加依赖与等待 | 私网 bypass 加 `no-resolve`；仍保留后续国内 GEOIP 解析判断 |
| P2 | Google/YouTube 被硬编码到智能组，绕过用户选择的代理/回退策略 | 使用统一默认代理组，显式自定义规则仍优先 |
| P2 | sing-box 自动测速切换主动打断既有连接 | 自动 urltest 切换保留已建立连接；手动 selector 切换仍可中断连接 |

创建流程的两项缺陷已通过执行真实前端处理函数并注入网络错误复现，但尚不能确认它们就是生产环境所报的同一问题。HTTP 响应本身丢失的重复提交问题不在本次修复覆盖范围内。

## 本次落地的移动网络策略

Mihomo 和 Egern 的默认故障回退直接包含节点，顺序为 TCP 节点、UDP 节点，再补齐其他节点，去重后由客户端探测。
服务器测得 UDP 可用不再提高它在默认回退中的优先级。UDP 仍可手动选择，且 TCP 全部不可达时可用于回退。
Egern 蜂窝网络、Wi-Fi 和未知网络均默认进入此回退组，避免蜂窝网络被固定在无备用的 TCP 组。
回退组定期探测间隔调整为 60 秒；这不是 60 秒内恢复的服务承诺，实际检测、连接重试和客户端缓存仍影响恢复时间。
代价是更多探测流量，以及默认策略优先稳定性、未必选择最低延迟节点。

sing-box 保留原有 urltest 选择方式，仅修复 Shadowsocks 能力声明和自动切换中断连接；没有伪造其不支持的 fallback outbound。
Loon 和 Egern 节点订阅只更新节点能力，既有用户规则需要在各客户端单独调整；完整策略变化要求导入完整配置。

## 待完成的生产诊断与优化方案

### 第一阶段：定位实际断点

在同一手机、同一节点上做 Wi-Fi / 4G / 5G 对照，记录运营商、系统、客户端/内核版本、协议、端口、时间与配置版本。
分别固定一个 TCP 协议和一个 UDP 协议，禁用自动选择的干扰；检查节点域名解析、TCP 建连、TLS/Reality 握手、HTTP 首字节及持续下载。
优先验证 VLESS Reality 或 Trojan 的现有 TCP 入口；若规划使用 443，先检查 Caddy/面板已有监听，使用独立 IP/Host 或已验证的接入设计，不能直接抢占 443。

每种网络与协议采集至少 30 次小请求和 3 次大文件传输，输出成功率、连接时间、TTFB p50/p95、吞吐和断流次数。
若只有 UDP 失败，维持 TCP 默认，检查运营商限制、节点防火墙、NAT 超时；若 TCP 同样失败，优先排查 IP/端口路径、DNS、握手和上游出口，不能只调 BBR。

### 第二阶段：弱网参数与恢复

- MTU 以客户端默认值作基线，试验 1400、1380、1280，分别比较大包、下载和视频；只有证据改善才保留变更，不统一盲改所有客户端。
- IPv4/IPv6 分别测连通、DNS64/NAT64 和握手。当前 Mihomo/Egern 禁用 IPv6，sing-box 为 prefer_ipv4；保留可回滚对照，验证后再启用双栈。
- 检查服务端拥塞控制、队列、CPU、重传与丢包，确认现有 BBR 状态后决定是否调整；UDP 协议的拥塞控制单独评估。
- 验证 Wi-Fi 到蜂窝和蜂窝到 Wi-Fi 各 10 次切换，记录 DNS 重建与新请求恢复时间；同时保留长连接，评估不主动中断后的存活/超时行为。
- 多节点部署先确保至少两个客户端可达的 TCP 入口，再扩大 UDP 协议组合。探测失败不把用户业务流量回退到 DIRECT。

### 第三阶段：智能路由统一与观测

统一规则意图为：本地网络 → 显式自定义规则 → AI 服务 → 国内域名 → 国内 IP → 默认代理。
DNS 与路由共同使用有版本的策略模型，并在生成后检查所有组引用与环路；加入真实内核配置校验，不依赖字符串存在性测试。
对 AI 长连接可增加独立稳定节点选择与切换迟滞，必须以真实流式请求的断流率验证，不能只凭 generate_204 延迟排序。
为规则集记录版本、校验和和更新时间；缓存不可用应展示降级状态。

当前仍需解决的审查发现：

1. **P2，规则诊断与执行不完全一致**：`server/routing/policy.js` 的 direct 模式在自定义规则之前返回，实际导出的客户端规则仍优先执行自定义规则；未知域名诊断使用服务端 DNS，客户端远程 DNS 可能得到不同 IP。应统一语义并区分“服务端推断”与“客户端实测”。
2. **P2，离线国内规则覆盖有限**：`server/singbox/protocol-catalog.js` 缓存不可用时的 inline `geoip-cn` 仅包含四个 DNS IP，不是完整中国 IP 集；Egern 路由侧主要依赖 `.cn` 与 GeoIP，不能宣称三端国内域名规则完全一致。应部署经校验的完整规则集、原子更新及上一版本回滚。
3. **P2，创建请求缺少幂等键**：当前修复覆盖 POST 成功后的刷新失败；如果 POST 响应丢失，客户端并不知道是否创建成功。建议新增幂等请求 ID、请求摘要和持久化结果，并把 Runtime 同步从长请求中解耦为可查询任务。
4. **P2，日期校验仅校验格式**：`server/database.js` 接受 YYYY-MM-DD 格式但未验证真实日历日期；新建表单默认到期日固定为 2026-12-31。应使用严格日期校验和明确的相对期限默认值，保留已有账号日期。

## 发布与验收

先在测试实例更新，刷新原订阅或导入新完整配置，确认选中的顶层策略实际指向故障回退；已有客户端可能保留手动选择。
用一个测试用户完成创建、登录、订阅下载、Runtime 实际认证、停用撤权，以及人为阻断 UDP / 一个 TCP 节点的回退验证。
随后小范围灰度；记录旧应用版本与旧客户端配置，出现成功率下降时回滚代码和客户端配置。
不修改既有主机/节点部署边界，不因路由优化额外给远程节点部署面板。

建议验收目标（目标值，非本次测得结果）：蜂窝测试请求成功率 ≥99%，断网后新连接恢复 p95 ≤15 秒，30 分钟流式会话无策略切换造成的主动中断；如果单一 generate_204 探测满足而业务不满足，验收仍不通过。
